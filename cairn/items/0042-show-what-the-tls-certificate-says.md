## Problem

quarry disables certificate verification so that a local HTTPS service with a
self-signed certificate can be probed at all — which is the right call, and
means it currently knows something about every TLS service and reports none of
it.

Local TLS goes wrong in specific, recognisable ways: a `mkcert` certificate that
expired, one issued for a hostname that is not the one you are using, a service
that is HTTPS-only while something in front of it assumes HTTP.

## Proposal

Report what the handshake already produced: subject and SAN names, issuer,
expiry, and whether it would have verified. A certificate that has expired, or
expires within a week, is worth marking — that is a class of local failure that
is otherwise diagnosed by reading a browser error.

## Acceptance criteria

- [x] subject, issuer and expiry in the detail pane for TLS services
- [x] an expired or nearly-expired certificate marked in the list
- [x] a name mismatch reported, since that is the common `mkcert` failure
- [x] verification stays off — this reports, it does not enforce

## 2026-09-15

The certificate had to be fetched separately: ureq turns verification off for us but has no reason to hand the certificate back, and in TLS 1.3 the Certificate message is encrypted, so there is no reading it off the wire. So one handshake, run with a verifier whose only job is to keep a copy on the way past. It accepts everything, which is the trust posture quarry already had — made explicit rather than hidden behind a builder flag.

rustls is named as a direct dependency rather than added: it was already in the tree under ureq, and nothing new is compiled.

The X.509 reader is hand-written and narrow — four fields, stepping over everything else without interpreting it. That was a deliberate trade against x509-parser and its nom dependency for a p2 item. What makes it defensible is the fixtures: three certificates generated by OpenSSL and committed as DER, so the parser is measured against something it did not write. It is also fuzzed over every truncation and a byte-flip sweep, because it is parsing whatever a socket sent.

Names are matched against the SANs, not the common name, which has not been authoritative for twenty years. A wildcard covers one label.
